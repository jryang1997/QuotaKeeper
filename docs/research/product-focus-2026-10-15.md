# 产品收口研究与实施依据

2026-10-15。上游 Magpie 固定到 [`95e7c6b`](https://github.com/yetone/magpie/tree/95e7c6bcc07629897f6703c31eaef477fcee4a13)。本轮目标是把订阅剩余额度和本机 Token 消耗做清楚。

## 一手证据

[Magpie README](https://github.com/yetone/magpie/blob/95e7c6bcc07629897f6703c31eaef477fcee4a13/README.md) 将产品定义为所有 Agent 的模型统一入口。它通过本地网关转发请求，修改 Agent 配置，额度用完后切到其他账号。QuotaKeeper 不承担这些职责；现有 [定位决策](../adr/0001-butler-positioning-quotakeeper.md) 已明确 Windows GUI 优先，TUI 冻结。

[Magpie reference](https://github.com/yetone/magpie/blob/95e7c6bcc07629897f6703c31eaef477fcee4a13/docs/reference.md) 区分实测速度和下限、保留配额读取时间和错误、明确缺价请求，不用当前登录身份补历史账号。[会话 Call 模型](https://github.com/yetone/magpie/blob/95e7c6bcc07629897f6703c31eaef477fcee4a13/internal/sessions/calls.go) 保留这些数据的来源边界。值得学习的是口径和证据，增加网关不符合本项目目标。

本地已有两套独立数据。服务商配额来自账号接口，本机 Token 来自 CLI 会话。两者没有可靠的逐请求账号关联，不能相加或推算成同一套餐的 Token 余额。

## 已观察的问题

- 旧导航包含额度、用量、分享、设置。用量可编辑模块约二十个，成就还会在额度页弹出通知。
- `QuotaPage.jsx` 先扣快照年龄，额度条带又扣一次。卡片和条带可能给出不同重置时间。
- “剩余”开关只改变卡片，条带仍显示已用。活动相对均值、缺少窗口的 Live 卡也参与额度排序。
- 用量筛选只控制部分模块。全局月度价值、模型榜等模块仍显示不同时间范围。
- 耗尽预测从 `5h/week/month` 文本猜窗口长度。账期不一定是自然月，无法保证预测可信。

## 选择和代价

比较了单页总览加展开，以及保留额度/Token 分页。采用后者，在额度首屏加本机今日、本周、本月 Token 摘要。用户打开应用就能看到两类数据，也能在独立 Token 页筛选历史。额度卡直接列出每个窗口，删除重复的额度条带。

删除成就、分享图片、拖拽布局、工作习惯与速度排行榜，以及 CLI 升级管理。保留现有主题和用户修改、通知、托盘、悬浮窗、局域网只读额度展示。隐藏的旧模块不再保留。

默认显示剩余，颜色仍表示已用程度带来的紧张度。所有重置倒计时只扣一次快照年龄；过了预定重置时刻显示待刷新，不擅自把额度回满。旧读数保留百分比但标明更新时间；不再显示从标签推测的耗尽时间或跨服务商建议。

Token 页固定展示范围内消耗、请求、API 等值参考、趋势、Token 桶和采集源分布。API 等值不是实际订阅账单，缺价保持可见。模型历史当前没有同样完整的筛选维度，因此不在筛选页混入全局榜单。

## 验收

行为契约见本轮 `.scratch/focus/spec.md`，决策和验证记录见 `.audit/product-focus.tsv`。以下是本机实际执行结果。

| 检查 | 结果 |
| --- | --- |
| 前端 `npm test` | 30 项通过 |
| Rust 核心 `cargo test --quiet` | 192 项通过，2 项忽略 |
| GUI Rust 测试 | 17 项通过 |
| 前端生产构建、Windows GNU release 构建 | 通过，已启动最终 exe 验证 |

最终原生窗口加载 `main-Dme0tO6f.js`。本机配额采集读到四家服务，五家尚未接入；DeepSeek 缺少 key，单独并入未接入列表。Token 读到五个采集源的记录，Claude Code 没有会话文件，界面保留读取失败提示。

在原生窗口按本月和 Codex 筛选，输入、输出、缓存读取、缓存写入分别为 15,738,356、1,549,011、376,550,400、0，与本地记录逐项相同。四家服务的 12 个窗口已核对已用与剩余切换，读数互补。原生窗口中的六个未接入项目能正常展开，底部导航不再挡住按钮。

标准评审发现两处完整性问题，均已修复并由评审复核。存在历史记录而当前窗口读取失败时，首屏显示未知；当前筛选未知时，导出按钮和导出处理函数都拒绝导出。浏览器用同一份受控数据验证了修复前的零和可导出、修复后的未知和禁用；采集成功且确实为空时仍显示零并允许导出。

原生窗口已验证中英文，检查结束恢复中文和原有剩余口径。浏览器在 720px、420px 下检查额度、Token、设置三页，无横向溢出，并查看了卡带主题。无采集数据的冷启动页面也能直接进入设置。最终原生进程没有 JavaScript 运行时错误。

本机原有局域网看板处于开启状态，本轮保持其设置。实开手机宽度页面，接口返回四家服务，页面显示实时状态，无输入或操作控件。图像证据保存在本机 `.audit/focus-final-native-zh.png` 和 `.audit/focus-final-native-en.png`。

本轮保留用户原有 `app.css`、`themes.css` 和 `gui/shots` 修改，因此没有清理这两个样式文件里的旧选择器。已删除功能的模块、测试和依赖已移除，也清理了燃烧率、旧维度文案及卡带拖拽样式。Vite 仍提示主 JS 包约 674kB、超过默认 500kB 提示阈值；生产构建和原生启动均已通过。
