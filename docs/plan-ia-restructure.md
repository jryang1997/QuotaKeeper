# GUI 信息架构梳理方案（2026-10-03）

> **实施状态：P0–P4 已于 2026-10-03 落地**（真机走查记录见 `docs/ux-review-2026-10-03.md`，截图 `gui/qa/shots/ux-*.png`）。与本文档的差异只有三处：①"面板"页合并进用量页后没有做"概览/自定义"双视图，改为单一模块板 + 工具栏"编辑布局"开关（少一个概念）；②设置页新增"关于与维护"的同时保留了页内目录（滚动高亮）；③新增成就系统（本文档未包含，见 ux-review）。P5（TUI/悬浮窗/托盘对齐）未做。

基线 `2ba3b16`（LAN 看板 Apple 质感重构后）。本文只谈**结构与命名**；视觉语言（分块条、点阵环、等宽标签、Apple 质感）是资产，全部保留。

## 0. 一句话诊断

GUI 把三件不同的事——**服务商额度**、**本机账本**、**界面定制**——摊在 5 个平级的可拖拽面板板上，没有一页对应"用户的一个问题"；设置页是 9 张卡的平铺列表；同一概念散在 2–3 个入口。要做的不是美化，是给每个页面一个唯一职责，给每个概念一个权威位置。

## 1. 现状：产品有 7 个面

| 面 | 内容 | 入口 | 结构 |
|---|---|---|---|
| GUI 主窗 | 配额 / Token 用量 / 面板 / 分享卡 / 设置 | 快捷方式、托盘"显示"、Ctrl+Alt+U | 侧栏 5 项，数字键 1–5 |
| 悬浮窗 | 当前套餐 5H/WEEK/MONTH 三环 | 托盘"悬浮窗" | 上下切换套餐 |
| 托盘 | 图标=最紧张等级色、tooltip、菜单 5 项 | 常驻 | 显示/刷新/悬浮窗/设置/退出 |
| LAN 看板 | 订阅配额 / Tokens / 活跃时段 3 视图 | 设置里开启，手机浏览器 | 时钟 + 视图切换 |
| 分享卡 | 1080 宽 PNG，7 个可选模块 × 2 配色 | GUI 第 4 页 | 独立模块系统 + 独立配色 |

## 2. 诊断

### 2.1 用户的第一问（"我还剩多少？"）没有单一落点

- **现象**：这页信息被拆到四处——配额页 hero 环（只显示"最紧张的一个窗口"，如 `Codex · 5 hours`）、下方卡片墙（要滚动、按 pin 排序）、悬浮窗、LAN 看板。同一个 hero 在用量页又出现一次（`UsageDashboard.jsx:180`）。
- **证据**：`QuotaPage.jsx:267-279`（hero=最紧张 limit）、`UsageDashboard.jsx:180`（重复 hero）、`main.jsx:124`（默认落在配额页）、TUI 有总览页而 GUI 没有（`src/ui/mod.rs:285`）。
- **影响**：用户要"读"页面而不是"看"结论；hero 只讲一家，其余八家得自己在卡片墙里找；hero 两处实现，会漂移——已漂移：配额页会过滤隐藏卡片（`QuotaPage.jsx:257`），用量页的 hero 不会（`UsageDashboard.jsx:167-169`），把一家隐藏了它仍可能是"当前最紧张额度"。

### 2.2 "面板/模块板"从能力变成了产品结构

- **现象**：配额、用量、面板三页 + 分享卡 = 四套可拖拽模块系统、四个 localStorage 布局键（`quota-layout.v1`/`usage-layout.v1`/`panels.v1`/`share-layout.v1`），外加分享页第五套配色（`SharePage.jsx:9`）。每张卡常驻 3 个操作按钮（置顶/锁定/移除），每页顶部常驻 4 个布局控件（`13/14`、全部锁定、重置布局、+选择模块，`ModuleBoard.jsx:256-268`）。
- **证据**：首屏截图里第一眼是"13/14 · 全部锁定 重置布局 +选择模块"，然后才是数据；分享页的画布里也嵌着这条工具条，只在导出瞬间隐藏（`app.css:1086-1088`），编辑态与成品不一致。
- **影响**：(a) 新用户先要学会"这块板可以拖"才能用；(b) 每页都逼用户回答"要不要自定义"，而 90% 的时候只想看数；(c) 同一组件在"模块板"与"固定面板"两种模式下行为不同（`ModuleBoard.jsx:250`、`:116`），维护与手感两处都要想。侧栏第 3 项叫"面板/Panels"——名字是容器不是内容，点进去之前不知道是什么；TUI 同位置叫"热力图/Heatmap"。

### 2.3 同一件事多个入口，权威位置不明

| 概念 | 入口 1 | 入口 2 | 入口 3 |
|---|---|---|---|
| 主题 | 设置·外观（5 选段） | 工具栏循环按钮 | `P` 键 |
| 卡片固定/隐藏 | 配额卡头 `◆`/`×` | 设置·配额卡片 | — |
| 已用/剩余 | 配额页工具栏 | TUI `u` 键 | 设置里没有 |
| 复制后清空剪贴板 | 卡片"套餐详情"的 key 区块（`CardDetails.jsx:100-103`） | — 无处可查 | — |
| 数据源自检/修复 | 欢迎弹窗（仅首次） | 设置底部"重新检测来源" | 设置·Agent 管理（第三套） |

- **影响**：用户建立不了"改这个去那里"的稳定预期；开发上每加一个偏好都要临时决定放哪，规则不存在。

### 2.4 设置页是 9 张卡的平铺滚动

- **现状顺序**：外观 → OpenCode Go key → GOAT key → DeepSeek key → Agent 管理 → 桌面常驻（托盘/快捷键/自启/通知/预测提醒/静默/LAN 看板/退出应用）→ 配额卡片（颜色/pin/hide/重检）→ 页脚（版本/恢复外观）。
- **问题**：三张 key 卡几乎一样（DeepSeek 那张连文案都没进 STR 表，`SettingsPage.jsx:312-313`）；"Agent 管理"会真的执行升级命令（有副作用）却和外观混排；LAN 看板是"把数据带出去"，却和托盘、自启、退出挤在一张卡里；"退出应用"（不可逆）紧挨 LAN 开关；"重新检测来源"语义属于数据源，却在"配额卡片"里。
- **影响**：查找成本高；危险操作与日常偏好同权重；列宽本身也不平衡（外观独占左列，其余 8 张全在右列）。

### 2.5 两套口径在 UI 里被混放，而 README 承认它们本来就对不上

- **现象**：配额百分比来自服务商，token 来自本机账本。但配额卡底部有"MONTHLY 419.65M tokens"（本机口径，不标来源）；配额页的 TOTAL TOKENS/TOTAL RUNS 在检测到 Command Code 时改用 GOAT 官方账期数据（`QuotaPage.jsx:54-86`，仅靠一行小 caption「当前账期 · Command Code 官方」提示，同一张卡在两种来源间切换）；用量页顶部又有"当前最紧张额度"（服务商口径）。
- **影响**："数字对不上"的困惑不是用户的错，是 UI 把两个口径放在同一视觉层级且不标来源。成熟做法：CodeBurn 把 quota 与 spend 分页；每个数字旁标 provenance（官方/本机/估算）。

### 2.6 三套实体在界面上没有建立映射

- **现状**：套餐（9 个 provider，有配额卡）↔ 本机来源（6 个 source，出 token）↔ Agent 程序（CLI 安装与升级）。Codex 同时是套餐卡、账本源、可升级 Agent；zcode/dsh/omp 只有源没有卡；glm/kimi/cursor 只有卡没有源。
- **影响**：这正是"内部逻辑不清楚"的来源——界面里没有任何一处把这张映射讲清楚。一个"数据源"区块（谁能给配额、谁能给 token、谁需要 key、谁需要登录）可以一次解决。

### 2.7 诊断信息占用首屏最贵的位置

- **现象**：`freshness-strip` 两枚徽章常驻每页第一行（`main.jsx:431-434`），文案是"服务额度 · 上次成功 <1m""本机用量 · 上次成功 <1m"——正常状态下这就是两行噪音；过期/失败才该出现的提示反而常态存在。
- **对照**：Claude `/usage` 只在失败时注 "Showing last-known usage"；CodexBar 把细节放 tooltip。

### 2.8 命名与本地化不统一（细碎但普遍）

- nav：GUI「面板/Panels」vs TUI「热力图/Heatmap」；GUI「Token 用量/Token Usage」vs TUI「Tokens」。
- 选项文案风格三种并存：`已用|剩余`（小写 `used/remaining`，`ui-data.js:160,208`）、`On/Off`、`中文/English`。
- 面板组件里大量大写英文硬编码（`TOKENS/RUNS/COST/DAYS`、`BUSIEST DAY`、`CACHE HIT`，`PanelBodies.jsx:223-288`），而 STR 表里备好了对应键（`panel_peak_hour` 等 10 个）没人用；`panels_add`（"添加图表"）也是死键，按钮写死"+ 选择模块"。
- **影响**：切到中文仍有一半标签是英文（视觉上可能是刻意的标签风格，但需要一次定规则）；术语表无法建立。

## 3. 对标：成熟产品怎么做（IA 层面）

1. **常驻"现在"，详情按需展开**——CodexBar 菜单栏弹出卡只放各 provider 窗口百分比 + `Resets in` 倒计时 + pace（[docs/ui.md](https://github.com/steipete/CodexBar/blob/main/docs/ui.md)）；配额与花费分页：quota 在 Plans/环，spend 在 Spend 页（CodeBurn）。
2. **首屏=一个主指标+分解清单，不是可搭建的报表**——Plausible 明确卖点 "no sub-menus and no need to build custom reports"（[guided-tour](https://plausible.io/docs/guided-tour)）；Vercel Analytics 用两个 tab 承载主图，面板按访问量排序（[docs](https://vercel.com/docs/analytics)）；OpenRouter Activity 头部五个数，然后排名卡（[docs](https://openrouter.ai/docs/guides/features/activity)）。
3. **周期是全局控件、命名统一、注明是否含当天**——Plausible：`Month to date`/`All time` 含当天、其他区间不含；Vercel 建议默认 `Last 30 days`（[limits/usage](https://vercel.com/docs/limits/usage)）。
4. **用 group-by 代替页面爆炸**——OpenRouter Explore：Metric + Group by + Rank by 一个构造器；tokscale：同一数据集 `--group-by model|client|session`。
5. **口径必须标出处**——Copilot 分 "included credits" vs "additional usage"；Cursor 分 "included usage" vs "on-demand"；Claude 对旧数据注 "Showing last-known usage"（[costs](https://code.claude.com/docs/en/costs)）。
6. **系统监视器的三层**——Activity Monitor：实时视图 / 历史 / 配置各自独立入口；Stats、iStat Menus 把"现在"放进常驻菜单。

**对本项目的取舍**：保留 TUI（终端第一公民）与 GUI 双前端；不追视图数量（与 `docs/research/codebase-audit-landscape-2026-10-01.md` 的结论一致）；学习点是"首屏给结论、周期统一、口径标注、配置收口"。

## 4. 目标结构：4 页，每页一个口径

```
配额  |  服务商额度（唯一口径）
用量  |  本机账本（唯一口径）＋分析视图
分享  |  带出去：图片分享卡 / 局域网看板
设置  |  维护：外观 / 数据源与凭据 / 桌面与通知 / 基准与货币 / 关于
```

规则三条：

1. **一页一口径**；跨口径的数据必须显式标注（如配额卡里的本机用量写成"本机本月 419.65M tokens"，而不是光一个 `MONTHLY`）。
2. **一个概念一个家**；其他入口只能是快捷方式（点了跳过去），不能是第二个编辑面。
3. **定制是能力，不是结构**：默认是排好的只读叙事；"编辑布局"是一个开关，打开才出现拖拽/锁定/重置/添加。

对照产品目的：「用量的数据支撑」由配额页 + 用量页摘要行承担；「数据分析的支撑」由用量页的分析视图承担；分享与设置是支撑面，不承载数据叙事。

配色与可见性的分工也是一条规则：**颜色归设置·外观，布局与显隐归所在页面**（所以"服务商配色"进外观，pin/hide 留配额页编辑模式）。

### 4.1 配额页

```
┌ 工具栏：已用|剩余 · 编辑布局 · 主题 · 刷新 ─────────────┐
│ 额度带（新）：9 家各一行 · 最紧张在前                    │
│   OPENCODE GO ▓▓▓░░░ 32%  重置 22d 0h   ● 正常          │
│   CODEX       ▓▓▓▓▓▓ 44%  重置 4d 20h   ▲ 快 13pt·≈2d17h│
│ 卡片墙（原样，去掉 hero）：每张=窗口条/重置/pace/到期/    │
│   可用模型/key/本机本月用量（标"本机"）                   │
│ 需关注提示（仅当有 ≥80% 或预测提前耗尽）                  │
└──────────────────────────────────────────────────────────┘
```

- 删除页首 hero（`QuotaPage.jsx:267-279`）；"最紧张"由额度带第一行表达，天然覆盖全部 provider 而不是一家。
- 卡片头三个常驻图标（置顶/详情/隐藏）收敛进一个 `⋯` 菜单：置顶状态用左侧色条表达；"套餐详情"按钮给图标+文字，不再是裸 `⌄`。
- pin/hide/颜色的权威位置就在本页（编辑布局模式下）；设置里不再重复，删除"配额卡片"分组。
- 本机本月用量行统一前缀文案。

### 4.2 用量页（吸收原"面板"页）

```
┌ 摘要行：今天 / 近 7 天 / 本月（tokens·请求·估价）────────┐
│ 最近 60 分钟 · 燃烧率 · 上次活动                          │
│ 筛选：范围(今天/昨天/近7天/近30天/本月/自定义) · Agent · 导出│
│ 视图：概览（默认，固定叙事）| 自定义面板（原模块板+12 模块）│
└──────────────────────────────────────────────────────────┘
```

- 原"面板"页 12 个模块并入本页；合并时**先去重**：模型榜（`panel_models` vs `ModelExplorer`）、项目榜、热力图/时段各保留一个实现。
- 默认"概览"= 现有模块按叙事顺序排好（趋势 → 模型 → 速度 → 缓存 → 热力/时段 → 项目/会话 → 纪录），布局工具收进"编辑布局"开关。
- 顶部一行口径说明保留（"本机账本 · 与服务商配额口径不同"），并把用量页里那个"当前最紧张额度"卡删除（配额数据回配额页）。
- 周期词表统一：今天 / 昨天 / 近 7 天 / 近 30 天 / 本月 / 自定义；不再出现"24 小时/14 天/周"混用。

### 4.3 分享页

- Tab 1「分享卡」：现有编辑器 + 重置布局键；布局工具条移出画布（画布内只留拖拽），消除"编辑态 ≠ 成品"；配色选项并入主题词表（"深海/暖纸"与主题 `theme_ink/theme_sand` 现在是两个词——统一为同一套命名）。
- Tab 2「局域网看板」：整个 LAN 区块从设置迁来（开关、地址、二维码、复制、安全说明）。两者都是"把数据带出去"。
- 导出 CSV/JSON 留在用量页筛选行（它导出的是当前筛选），但文案统一为"导出"。

### 4.4 设置页（5 组，左栏目录 + 右侧内容）

| 组 | 内容 | 来源 |
|---|---|---|
| 外观 | 语言、主题、字体、密度、动效、**服务商配色** | 原"外观" + 卡片颜色 |
| 数据源与凭据 | **服务商直连**（三张 key 卡合并为一个列表：每行 provider + 状态 + 输入/移除）；**本机数据源**（6 源：路径、状态、修复步骤——欢迎弹窗的内容常驻于此）；Agent 管理（升级） | 原三张 key 卡 + 欢迎弹窗 + Agent 卡 |
| 桌面与通知 | 托盘行为、全局快捷键、开机启动、额度通知、耗尽预测、夜间静默、**悬浮窗**（开关） | 原"桌面常驻"去掉 LAN 与退出 |
| 基准与货币 | 月费基准、显示货币、汇率 | 原"套餐基准" |
| 关于与维护 | 版本、重新检测、恢复默认、退出应用 | 原"配额卡片"残留 + 页脚 |

- 欢迎弹窗保留（首次引导），但它是进入"数据源"组的漏斗，不再是唯一能看修复步骤的地方。
- 删除"配额卡片"组（pin/hide 归配额页，颜色归外观，重检归关于/数据源）。

### 4.5 其余三个面

- **悬浮窗**：设置·桌面与通知里的开关 + 配额页一个快捷入口；内容口径不变（5H/WEEK/MONTH 三环）。
- **托盘**：菜单保持 5 项；tooltip 不变。
- **LAN 看板**：3 视图与主窗口径对齐（订阅配额 → 配额；Tokens/活跃时段 → 用量）。
- **TUI**：本方案不动 TUI。仅记一项后续可选对齐：TUI"总览"与 GUI"用量"是同一口径，未来可考虑改名为"用量"、并把"热力图"作为页内视图（与 GUI 合并方式同构）。

## 5. 术语表（写进 STR 与文档，一处定义）

| 概念 | 中文 | 英文 | 说明 |
|---|---|---|---|
| 服务商窗口限制 | 配额 / 窗口 | quota / window | 5h、周、月窗口；只指服务商口径 |
| 本机记录 | 本机用量 / 账本 | local usage / ledger | 只指本地 token；跨页出现时前缀"本机" |
| 服务商 | 服务商 | provider | 有配额卡的一方（含 DeepSeek 余额） |
| 本机数据源 | 数据源 | source | 6 个 CLI 数据目录 |
| CLI 程序 | Agent | agent | 发起调用的工具（Codex/Claude Code/…） |
| 状态 | 正常 / 关注 / 耗尽 | ok / warning / exhausted | 与 `status_for` 口径一致，不另造词 |
| 周期 | 今天/昨天/近 7 天/近 30 天/本月/自定义 | today / yesterday / last 7 days / … | 全局统一 |
| 指标 | Token 数 / 请求数 / 成本（估价 ≈） | tokens / requests / cost | 不再用 msgs/runs/calls 混称 |

大写英文微标签（`TOTAL TOKENS` 之类）保留为**风格标签**，但规则固定：风格标签一律英文、不参与 i18n；可读文案一律走 STR。删掉备用未用的死键，或让它们接上。

## 6. 落地批次（每批可独立验收、独立提交）
