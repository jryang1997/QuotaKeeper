# 按模型查看用量并解释 API 等值

先交付按日期查看模型用量，再交付金额出处。保留订阅额度、Token 用量和设置三个主导航。每个可运行的小步分别测试、提交并推送，确认远端已有提交后再继续。

## 按模型统计

原始会话记录已经有模型名。每日和小时聚合需要保留模型维度，桌面筛选和导出读取同一份账本。默认按模型展示分布，也能切回采集源。

验收覆盖以下行为。

- 日期、采集源和模型同时控制总量、趋势、Token 构成和导出。
- 原始模型名与分组名分别保留。未知模型不丢失，不用当前配置回填历史。
- 模型合计等于当前筛选总量。历史查询不借用固定近 30 日榜单。
- Token 总量包含缓存读取和写入。推理 Token 已含在输出中，不再相加。
- 归一化记录数称为调用记录数，不承诺它等于精确 API 请求数。

## 金额出处

API 等值参考不是订阅实际扣费。分别显示来源报告金额、估算金额和未估价记录数。

价目查询需要保留采用条目、匹配方式和更新时间。家族价与补缺缓存桶价要说明近似。一次采集使用同一份价目快照，导出保留该快照的说明。历史金额按当前价目重估，不恢复历史账单。

有消耗却没有对应缓存单价时，不把缺价当免费。缺少完整单次请求与缓存时长时，不增加上下文分档或猜测缓存时长。

## 本轮不做

不增加路由、模型或账号自动切换、新分析页、账号管理、额度历史和耗尽预测。本机 Token 与服务商剩余额度继续分别展示。

## 验证

先记录原版测试结果，再验证核心聚合、桌面序列化、导出与前端同一组固定样本。用本地浏览器操作现有页面，覆盖正常、空、未知模型和采集失败状态。浏览器验证不替代 Windows 原生窗口验收。

研究基线为 `166fd11328bdccb2ea07110d5d47ea3e5084f314`。本轮开始时的前端测试为 30 项通过。Rust、GUI 与后续新增检查结果随各步提交记录，未完成的检查不记为通过。
