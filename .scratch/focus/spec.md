# QuotaKeeper 产品收口验收

用户授权在本轮自主研究、重构、添加和删减，目标是把 Token 消耗与订阅剩余额度做精。保留用户已有 app.css、themes.css 和 gui/shots 改动。所有采集保持只读，不改 CLI 配置。

## 行为

1. 主导航仅“订阅额度”“Token 用量”“设置”。首屏显示本机今日、本周、本月 Token，并展示已接入服务的所有额度窗口。未接入服务集中展开，避免占满首屏。
2. 额度默认看剩余，保留已用切换。每个窗口的百分比、重置时间和数据更新时间口径一致。旧读数明确标记，不把已过重置时刻解释为已回满。活动均值不能作为订阅额度显示。移除从标签猜窗口长度得出的耗尽预测和跨供应商切换建议。
3. Token 页用固定布局，日期和采集源筛选驱动全部统计。保留消耗、请求、API 等值参考、趋势、Token 桶拆分、采集源分布与导出。API 等值明确不代表订阅账单，缺价明确显示。移除成就、排行榜、工作习惯分析、拖拽布局和与当前筛选不一致的全局模块。
4. 删除成就与分享图片生成。移除 CLI 安装升级管理。保留数据诊断、凭据、通知、托盘、悬浮窗、局域网只读额度展示，后者放在设置里。
5. 中英文均可使用；保持既有外观偏好和用户主题修改。删除失去调用方的模块、测试和依赖，不保留隐藏的旧页面。

## 验证

- 改前已观察浏览器真实 React 界面。前端基线 39 项通过；Rust 核心 200 项通过、4 项 ignored。
- 配额边界用 node:test 覆盖剩余百分比、只扣一次时间、已过重置、旧读数与活动回退。Token 范围筛选和导出沿用现有行为测试，并补确有风险的边界。
- 改后构建前端和 Windows GUI，运行真实程序并观察新界面；浏览器验证导航、筛选、展开、设置、窄窗和英文。运行本机采集 smoke，只报告实际读到的结果。
- 独立评审检查实现与本验收和代码约定，并修完可操作问题。
